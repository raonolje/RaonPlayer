# v0.5 하드테스트 실행

소스 폴더에서 실행합니다. Node.js 및 `npm install`, 로컬 FFmpeg·FFprobe가 필요합니다. 실제 테스트 미디어는 기존 `outputs/youtube-test/media`를 사용하며 별도 배포 영상 파일이 필요합니다. 합성 픽셀을 검사하는 시험이므로 다른 GPU 작업과 병렬 실행하지 마세요.

```powershell
$env:HARD_EXE='../player-windows-v0.5/RaonLocalPlayer-win32-x64/RaonLocalPlayer.exe'
$env:TEST_OUT='../diagnostic-v05'
npm test
npm run test:preview
npm run test:pressure
npm run test:hard
npm run test:e2e
node tests/release-smoke.e2e.mjs
node tests/display-routing.e2e.mjs

$env:STRESS_SECONDS='600'
$env:STRESS_ROUNDS='3'
$env:BLACK_SAMPLE_EVERY='12'
$env:STRESS_LABEL='final-alpha'
$env:STRESS_MIXED='0'
npm run test:extreme

$env:STRESS_LABEL='final-mixed'
$env:STRESS_MIXED='1'
npm run test:extreme
```

`HARD_EXE`를 지정하지 않으면 소스로 실행합니다. 시험 프로필은 일반 사용 프로필과 분리합니다. `TEST_PROFILE`을 새 경로로 지정하면 네이티브 디스크 루프 캐시도 새로 생성합니다. 최종 두 시험 모두 격리된 시험 프로필의 디스크 캐시를 재사용했습니다. 초기 혼합 시험에서는 새 프로필에서 캐시 생성도 확인했습니다. 각 회차에서 CPU 프레임·GPU 텍스처는 다시 준비하고 반환합니다.

프레임 순서·텍스처 키·출력 창 순서는 매 합성마다 검사하고, 검정 화면 검사는 12틱당 한 번, 별도 Worker의 축소 스냅샷 읽기로 수행합니다. Worker가 처리 중이면 새 검사를 쌓지 않으며 실제 검사 횟수와 생략 횟수를 기록합니다. 시험 페이지에만 CDP CSP 우회를 사용해 계측 Worker를 만들며 배포 앱의 CSP는 변경하지 않습니다. `BLACK_SAMPLE_EVERY=1`은 비동기 색상 검사를 매 틱 요청하는 관측 부하 비교용입니다. 이전 기준선 시험의 동기 GPU 읽기와는 다르며, 실제 출력의 지연 측정과 구분해야 합니다. 기본 합격 기준은 변화 간격·루프 경계 간격 각각 100ms 미만, 검정·누락·GPU 오류 0, 매 회차 캐시 예약량 0입니다. 실제 최대값은 결과 JSON에 남습니다.

`tests/fingerprint-build.mjs`는 최종 ASAR의 주요 코드와 모든 UI 파일이 소스와 일치하는지 검사합니다. 배포 파일을 바꿨으면 모든 최종 검사를 다시 수행합니다.
