# RaonPlayer 소스 인계 기준

이 저장소의 초기 소스는 MOGRT 기능이 없는 Raon Local Player v0.11.0입니다. 2026-10-24 검증한 원본에서 가져왔으며, 5.1 오디오 기획은 아직 구현하지 않았습니다. 일반 재생의 실제 6채널 출력은 미검증이고 구간 반복 오디오는 48kHz 스테레오입니다. 핑퐁 생성본은 무음입니다.

설치: Node.js 22.12 이상에서 `npm ci` 후 `npm start`를 실행하세요. FFmpeg/FFprobe는 별도 설치가 필요합니다. `npm test`는 단위 검사입니다. 전체 실제 미디어 검사는 별도 영상과 Windows/GPU 환경이 필요하므로 소스 업로드만으로 다시 통과한 것이 아닙니다.

검증 결과: [v0.11 4시간 검사 보고서](docs/4시간_검증_결과_v0.11.md). 문서와 일부 시험 스크립트의 v0.5 경로는 과거 기본값입니다. 패키지 검사는 `HARD_EXE`와 `RELEASE_ROOT`에 검사 대상 v0.11 폴더를, `TEST_OUT`에 별도 결과 폴더를 명시하세요. 실행 패키지, node_modules, 대형 진단 기록과 외부 실사 시험 영상은 이 저장소에 포함하지 않습니다.

아래는 기존 사용 안내와 변경 이력입니다.
# Raon Local Player v0.11

인터넷 없이 로컬 파일로 동작하는 Windows 데스크톱 플레이어입니다. 일반 재생은 Chromium 디코더, 반복 재생은 미리 디코딩한 프레임과 WebGL 합성을 사용합니다. 기획서의 최종 C++/D3D 엔진을 완성한 버전은 아닙니다.

## v0.11 · 4시간 검증

동일 패키지로 큐 전환 7,201.515초와 루프 7,200.3991초를 통과했습니다. 원시 I420/I420A 출력 업로드, 비동기 GPU 준비, 재생 프로세스 우선순위와 Windows 기본 화면 BufferQueue 경로를 적용했습니다. 상세 수치·실패 이력·메모리 추세·검증 한계는 `4시간_검증_결과.md`를 확인하세요. 아래의 v0.5 및 이전 항목은 변경 이력입니다.

## v0.5 반복 업로드·미리보기 부하와 계측 개선

- 24fps 알파를 포함한 모든 반복 프레임의 GPU 텍스처를 READY 단계에서 준비합니다. 재생 중 반복 프레임 업로드가 GPU를 기다리며 멈추던 경로를 제거했습니다. 활성·대기 구간 합계 2GiB 예산은 유지합니다.
- 독립 출력 창마다 Worker가 영상 변환·그리기를 담당합니다. 재생 스레드에서는 프레임 소유권을 복제해 순서대로 전달하며, 출력 대기열 8개 초과 또는 Worker 오류는 HOLD로 알립니다. 출력이 밀리는 상태를 프레임 폐기로 숨기지 않습니다.
- Windows 재생 프로세스는 High(실시간 아님) 실행 우선순위를 사용합니다. 앱 종료와 함께 적용이 끝나는 프로세스 설정이며, 운영 화면의 긴 작업과 출력의 실행 순서를 분리합니다.
- 운영용 JPEG 압축과 축소 캔버스 작업은 별도 Worker에서 실행합니다. PGM/PVW가 바뀌었을 때만 새 미리보기를 만듭니다.
- 운영 창의 수신 확인이 올 때까지 다음 미리보기 캡처·압축을 중지합니다. 화면 정지 시 버려질 JPEG를 계속 만들던 비용을 제거했습니다.
- 재시험에서 160.8ms 간격을 재현했고, 해당 시점 시험용 GPU 동기 픽셀 읽기 자체가 120.4ms를 차지함을 계측했습니다. 프레임 순서·텍스처·출력 갱신은 매 합성마다 검사하며, 색상 읽기는 별도 표본 검사로 구분합니다.
- 시험 결과·최대 간격·남은 검증 범위는 함께 제공하는 v0.5 보고서를 확인하세요. 8K60 및 물리 10개 출력의 신호 품질을 검증한 버전은 아닙니다.

## v0.4 재생 격리와 부하 최적화

- 운영 화면과 재생 엔진을 서로 다른 프로세스에서 실행합니다. 일반 영상·알파 반복·오디오는 재생 엔진이 담당합니다.
- PGM/PVW/레이어/10뷰 독립 출력은 재생 엔진의 원본 해상도 캔버스를 직접 공유합니다. 운영 화면의 PGM/PVW는 480px 폭, 최대 10fps의 압축 미리보기입니다. 운영 화면에 부하가 생겨도 독립 출력은 계속 재생합니다.
- 출력 창 10개를 시작 시 준비하고 재사용합니다. 재생 중 창 생성·전체 운영 화면 로딩을 피하며, 닫은 출력 창은 대기 상태로 돌립니다.
- 30fps를 넘는 고속 반복은 GPU 텍스처도 READY 단계에서 준비합니다. GPU 업로드를 합성 틱 사이에 나눠 처리하며, 재생 중 프레임마다 다시 업로드하지 않습니다. GPU 텍스처 예산은 별도 2 GiB이고 BLACK·미리보기 해제로 반환합니다.
- 합성 직후 출력 창을 함께 갱신하고, 영상이나 레이어 설정이 바뀐 프레임만 다시 합성·복사합니다.
- 반복 VideoFrame 생성은 별도 작업 스레드로 분리했습니다. 같은 구간의 준비는 공유하며, 빠른 선택은 진행 중인 준비 뒤 가장 최근 선택으로 합칩니다.
- 자동 큐 진행도 재생 엔진이 처리합니다. 운영 화면이 잠시 응답하지 않아도 자동 체인이 진행합니다.
- GO 완료는 첫 합성 프레임 출력 이후 알립니다. 대기 중 GO보다 HOLD/BLACK 명령이 우선합니다.
- 운영 미리보기 전송은 수신 확인 방식으로 제한해 운영 창이 멈췄을 때 이미지가 계속 쌓이지 않습니다.
- 기존 v0.3 아이콘·프로젝트·루프·출력 기능을 유지합니다. 검증 수치와 시험 조건은 함께 제공되는 극한 테스트 보고서를 참조하세요.

## v0.3 수정 사항

- 빠른 재개/정지의 마지막 명령을 보존하고, 다음 큐 준비 중 HOLD·BLACK이 자동 진행을 취소합니다.
- 이미지 IN/OUT, 짧은 자동 큐의 연속 진행, 재생 중 삭제한 큐의 자동 진행을 보완했습니다.
- 30fps 캔버스에서는 60fps 소스도 반복 캐시를 30fps로 준비합니다. 출력 크기를 바꾸면 PVW를 다시 준비합니다.
- 자동 저장을 순서대로 원자적으로 기록합니다. 복구 후 저장은 새 파일 선택으로 진행해 이전 프로젝트를 덮어쓰지 않습니다.
- 누락 파일 재연결 시 이전 핑퐁 연결을 무효화하고, 입력 칸에서 Ctrl+S를 사용할 수 있습니다.
- 긴 큐 목록은 기존 행을 재사용해 GO 중 전체 표를 새로 만들지 않습니다.
- 출력 창 ESC·더블 클릭 경로, 단일 앱 실행, 앱·실행 파일·바탕화면 아이콘을 정리했습니다.
- 일시 지연은 순서대로 따라잡고, 250ms 이상 밀린 상태가 1초 지속되면 HOLD 오류로 전환합니다. 원인을 줄인 뒤 재개하거나 BLACK으로 비우세요. GPU 컨텍스트 손실은 한 번 알리고 안전하게 정지하며 앱 재시작이 필요합니다.

## 빠른 시작

배포 폴더의 **RaonLocalPlayer.exe**를 실행합니다. 같은 폴더의 DLL·resources·locales를 함께 보관해야 합니다. 실행 파일만 다른 폴더로 옮기지 마세요.

바탕화면 바로가기는 배포 폴더의 `바탕화면_바로가기.cmd`로 만들 수 있습니다. 앱 폴더를 이동했다면 다시 만드세요. 바로가기는 새 실행 파일의 아이콘을 사용합니다.

1. 상단 **데모**를 누릅니다. 7개의 큐와 테스트용 영상이 불러와집니다.
2. **GO** 또는 **Space**를 누르면 준비된 PVW가 지정 레이어의 PGM으로 전환됩니다. 다음 큐를 자동으로 준비합니다.
3. GO를 차례로 눌러 네 개의 알파 영상을 서로 다른 레이어에 합성해 보세요.
4. **출력·설정**에서 PGM 또는 **10뷰 격자 그룹**을 선택하고 **독립 출력 창 열기**를 누릅니다.
5. 출력할 모니터를 선택해 전체 화면으로 열 수 있습니다. **ESC**로 전체 화면을 해제합니다.

실제 파일은 **불러오기** 또는 파일 드래그로 추가한 다음 **큐 추가**를 누릅니다. 기본 오디오는 음소거이며 레이어별로 해제할 수 있습니다. PGM은 현재 출력, PVW는 다음 큐의 첫 프레임을 포함한 합성 미리보기입니다.

## 구현된 기능

- MP4 / WebM 영상 및 PNG / JPEG / WebP 이미지의 로컬 재생
- 다음 큐 프리로드 후 CUT, 큐 순서 변경·복제·삭제, 종료 후 다음 큐 실행
- 레이어 4개, 알파 합성, 개별 불투명도·음소거·표시·X/Y·배율
- 자유 비율 캔버스, FIT / FILL·CROP / STRETCH
- IN / OUT 구간, 정방향 반복, 지정 구간 핑퐁 캐시 생성
- 독립 PGM·PVW·레이어 원본 출력 창, 최대 10개 창, 모니터 지정
- PGM·PVW·레이어 소스를 배치하는 가상 뷰 10개와 격자 그룹
- HOLD / RESUME / BLACK, GO·BLACK·레이어 조작 잠금
- 한글 경로를 지원하는 `.lmp` 프로젝트 저장·열기·누락 파일 재연결
- 자동 저장 복구, 원본 미디어와 루프 캐시를 함께 복사하는 **패키지 저장**
- 재생되지 않는 영상의 로컬 **호환 변환**: 일반 영상은 H.264 MP4, 알파 영상은 VP9 WebM

## 루프 설정

큐를 선택해 IN / OUT을 초 단위로 입력합니다. 루프를 **구간 반복** 또는 **핑퐁**으로 바꾸세요. 핑퐁은 **핑퐁 캐시 생성**을 먼저 누른 후 READY 상태에서 GO로 실행합니다.

핑퐁 캐시는 양 끝의 중복 프레임을 제외한 정방향+역방향 파일입니다. 캐시에서 오디오는 제거됩니다. 한 구간은 최대 12초, 비압축 RGBA 추정 1 GiB 이내로 제한합니다. 8K 영상에서는 더 짧은 구간이 필요합니다. 구간이나 모드를 수정하면 캐시를 다시 생성해야 합니다.

v0.2부터 반복 구간 전체를 READY 단계에서 디코딩합니다. 재생 중 탐색하지 않고 마지막 프레임 다음에 첫 프레임을 출력합니다. 핑퐁 캐시도 같은 방식으로 반복합니다. 오디오가 있으면 별도의 PCM 루프를 Web Audio 시계에 맞춰 재생합니다. 핑퐁 생성본은 영상 전용입니다. 원본 자체의 마지막·첫 장면 차이와 오디오 파형 불연속은 그대로 남습니다.

프레임은 원본 해상도와 최대 60fps로 준비합니다. 활성 4개 레이어와 다음 큐를 합친 디코딩 캐시는 최대 **1 GiB**이며 동일 구간은 공유합니다. 한도를 넘으면 READY 대신 오류를 표시하므로 구간을 줄이세요. GPU 텍스처와 앱 자체 메모리는 별도입니다. 짧은 고해상도 반복도 메모리를 크게 사용합니다. 준비 시간과 디스크 캐시가 추가로 필요합니다.

**일시정지**는 현재 프레임과 재생 위치를 유지합니다. 한 번 재생 큐는 종료 후 마지막 프레임을 홀드합니다. **BLACK**은 모든 활성 레이어를 비웁니다.

## 저장과 오프라인 이동

**저장**은 프로젝트 설정과 미디어 경로를 기록합니다. 원본 파일을 이동하거나 삭제하면 다시 연결해야 합니다.

**패키지 저장**은 선택한 폴더에 새 공연 폴더를 만들고 원본·호환본·핑퐁 영상과 상대 경로 프로젝트를 복사합니다. 다른 PC로 가져갈 때는 이 폴더 전체를 옮기세요. 디코딩 프레임 캐시는 PC별 앱 데이터에 별도로 생성되므로 이동한 PC에서도 FFmpeg가 필요합니다. 반복 큐가 READY가 된 다음 재생을 시작하세요.

자동 저장본은 앱 데이터 폴더에 보관됩니다. 앱을 열고 **자동 저장 복구**를 눌러 불러올 수 있습니다. 자동 저장은 일반 프로젝트 저장을 대체하지 않습니다.

## 실행 환경

- Windows x64, GPU 드라이버와 WebGL 가속
- 한 번 재생과 프로젝트 열기는 배포 폴더만으로 실행할 수 있습니다. 인터넷·계정·외부 미디어 서버를 사용하지 않습니다.
- 메타데이터 검사, 호환 변환, 핑퐁 생성과 무공백 반복 준비에는 별도로 설치된 FFmpeg / FFprobe가 필요합니다.
- 앱은 `C:\ffmpeg\bin\ffmpeg.exe`·`ffprobe.exe`, PATH 또는 `FFMPEG_PATH`·`FFPROBE_PATH` 환경 변수를 찾습니다. 현재 작업 PC에서는 기존 설치본으로 검증했습니다.
- FFmpeg 바이너리를 이 배포본에 포함하지 않았습니다. 별도 설치본의 라이선스는 해당 배포처를 따릅니다.

## 이번 버전의 범위와 제한

**8K60, 10개 독립 물리 출력 동시 운용은 검증 전 목표입니다.** 7680×4320 캔버스를 선택할 수 있지만, 그것이 해당 부하에서 60fps를 보장한다는 뜻은 아닙니다. 측정 FPS는 합성 루프 속도이며 디코더의 실제 고유 영상 프레임 수나 HDMI/SDI의 프레임 드롭률이 아닙니다.

기능 검사는 테스트 패턴과 실제 Blender 공개 영화 영상을 함께 사용합니다. 검은 프레임·순서 누락·캐시 예산·출력 캔버스 갱신을 계측하며, 이는 HDMI/SDI 신호를 계측기로 측정한 결과가 아닙니다. 과부하·GPU 손실·디스크 고장까지 무조건 무중단으로 보장하지는 않습니다. 250ms 이상 밀린 상태가 1초 지속되면 오류와 HOLD로 알립니다.

- 기본 직접 재생은 Chromium 지원 코덱에 한정됩니다. HAP / ProRes / 특수 MOV는 **호환 변환**을 사용하세요.
- 프레임 정확도를 보장하는 네이티브 타임라인, 크로스페이드, 하드웨어 프레임록/젠록, SDI SDK, 타임코드·OSC·MIDI는 아직 구현하지 않았습니다.
- 독립 출력은 같은 PC 안의 별도 재생 엔진 캔버스를 공유합니다. 네트워크 송출은 없습니다. 여러 장치 사이의 물리적 동기화는 보장하지 않습니다.
- 프로젝트에 가상 뷰 소스 지정은 저장됩니다. 독립 창의 실제 위치·열림 상태는 현재 세션에만 유지됩니다.
- 패키지 저장은 파일 크기에 따라 시간이 걸리며 원본을 삭제하지 않습니다.
- 디지털 서명과 설치 프로그램을 포함하지 않은 개발용 포터블 빌드입니다.

## 개발·검증

Node.js 22.12 이상과 npm으로 소스 폴더에서 실행합니다.

```powershell
npm ci
npm start
```

단위 검사와 실제 Electron 앱 검사는 다음과 같습니다. 앱 검사는 FFmpeg가 필요하며 `tests/fixtures`의 결정적 테스트 미디어를 사용합니다. 외부 HTTP(S) 요청을 막은 상태에서 로컬 동작을 시험합니다.

```powershell
npm test
npm run test:e2e
npm run test:loops
npm run test:hard
npm run test:soak
npm run package
```

`src/main.cjs`: 로컬 파일 접근·미디어 검사·프로젝트·FFmpeg 작업·출력 창

`src/ui/engine.js`: 디코더 덱·다음 큐 준비·WebGL 합성·독립 렌더 시계

`src/ui/loop-cache.js`: 무공백 반복용 평면 프레임·PCM 캐시와 공유 메모리 예산

`src/ui/render-host.js`: 별도 재생 프로세스·자동 큐·출력 공유

`src/ui/remote-engine.js`: 운영 명령·제한된 미리보기 수신

`src/ui/frame-loader.js`: 반복 프레임 준비 작업 스레드

`src/ui/app.js`: 운영 화면·큐·레이어·출력·프로젝트 상태

`src/core.cjs`: 범위 요청·프로젝트 검증·루프 캐시 예산
